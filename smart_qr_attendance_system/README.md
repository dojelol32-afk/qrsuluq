# Smart QR Attendance Management System (v2)

Node.js/Express backend + Supabase (PostgreSQL) + two static HTML pages (student / teacher).

## How it works

1. The teacher logs in on `teacher.html` and starts a session. The server creates a secret and keeps it private.
2. The teacher page shows a QR code that changes every N seconds. It contains the session id and a one-time TOTP code generated by the server.
3. The student logs in on `index.html`, scans the QR with the phone camera, and the server validates the TOTP code, the session, and the student's identity (from the login token).

## Setup

### 1. Supabase
- Create a project at https://supabase.com.
- SQL Editor: if you used the old tables, first run
  `DROP TABLE IF EXISTS attendance_records, qr_sessions, courses, users CASCADE;` (this deletes old data), then run all of `schema.sql`.
- Settings -> API: copy `Project URL` and the `service_role` key (keep it secret, backend only).

### 2. Local run
```bash
cp .env.example .env        # fill in the values
npm install
npm run dev
```
Generate a strong `JWT_SECRET`:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 3. Create accounts
```bash
node create-user.js --role Teacher --name "اسم المحاضر" --email teacher@uni.edu --password "StrongPass123"
node create-user.js --role Student --name "اسم الطالب" --email student@uni.edu --number 4423 --password "StrongPass123" --department CS --year "Year 2"
```

### 4. Deploy backend on Render
- Push the backend files (everything except the two `.html` files) to GitHub.
- Web Service settings: Build `npm install`, Start `npm start`.
- Environment variables: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `JWT_SECRET` (32+ chars), `NODE_ENV=production`, `ALLOWED_ORIGIN` (exact origin of your site, e.g. `https://yourdomain.com`, no trailing slash).

### 5. Deploy the pages (Namecheap / any static host)
- Upload `index.html` and `teacher.html` to `public_html`.
- The site must use **HTTPS**, otherwise the phone camera will not work.
- `API_BASE_URL` at the top of each page's script must be your Render URL.

## API

| Method | Path | Who |
|---|---|---|
| POST | `/api/auth/login` | everyone |
| POST | `/api/sessions` | Teacher/Admin |
| GET | `/api/sessions/:id/token` | session owner |
| POST | `/api/sessions/:id/end` | session owner |
| GET | `/api/reports/session/:session_id/csv` | session owner |
| POST | `/api/attendance/scan` | Student |

## Known limits
- A student could photograph the QR and send it to a friend who is not in the room; the code only lives for ~20-30 seconds, which limits but does not eliminate this. Stronger options: location check, or showing the QR on a projector only.
- IP address is stored for reference but not used to block students, because a campus Wi-Fi shares one public IP.
